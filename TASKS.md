отмечает `[x]` и коммитит. Одна задача — один коммит. Не брать больше одной за запуск.

- [x] **Утечка таймера.** *(2026-08-13)* Путь из формулировки задачи устарел
      (`src/components/Level1Game.tsx` → актуальный `src/components/GameLevel.tsx`
      после переработки на Tailwind + Framer Motion), сама проблема была на
      месте: `setTimeout(..., 1400)` в `handleCardClick` (переход к следующему
      раунду / завершение уровня) не сохранялся и не очищался, поэтому выход
      в меню кнопкой «Меню»/`onBack` во время 1.4-секундной анимации ответа
      оставлял колбэк висеть и он дёргал `setRound`/`generateNewPair` или
      `onLevelComplete` уже после размонтирования `GameLevel`. Исправлено:
      id таймера теперь хранится в `useRef` (`nextRoundTimeoutRef`),
      предыдущий таймер очищается перед постановкой нового, и добавлен
      `useEffect` с cleanup, который чистит его при размонтировании
      компонента.

- [x] **Ничья по весу.** *(2026-08-12)* Проект с прошлого прогона был полностью
      переработан (Tailwind CSS + Framer Motion), поэтому пути из формулировки
      задачи устарели: `src/data/animals.ts` → `src/data/level1.ts`,
      `src/components/Level1Game.tsx` → `src/components/GameLevel.tsx`. Сама
      проблема осталась: у `grizzly-bear` и `zebra` в `src/data/level1.ts`
      одинаковый `value: 350`, а `generateNewPair` в `GameLevel.tsx` считал
      верным всегда `itemA` при равенстве значений (`isAMax = itemA.value >=
      itemB.value`), из-за чего верный ответ по `itemB` штрафовался на −2.
      Исправлено: `generateNewPair` теперь при равных `value` у первой
      случайной пары ищет в перетасованном списке следующего кандидата на
      `itemB` с другим значением, прежде чем определять корректный ответ.
      Решение общее для всех уровней, не только для этой пары.

- [x] **Картинки животных не грузятся в проде (часть 1 из 2): локальные фото и
      битые хотлинки.** *(2026-08-10)* Проверено на
      https://supremegoogle.github.io/GuessWhat/ — `<img>` на `images.unsplash.com`
      отдаёт `error` (хотлинк заблокирован в проде и даже недоступен из этого CI —
      прямая проверка `curl` на `images.unsplash.com` и `upload.wikimedia.org`
      вернула `403`), поэтому карточки показывали emoji-фолбэк вместо фото. Сделано:
      9 готовых JPEG в `public/animals/` сжаты с ~0.6–1 МБ / 1024×1024 до
      ≤150 КБ / 800×800 / 72 dpi (mozjpeg, без перекодирования размеров сверху);
      `imageUri` в `src/data/animals.ts` для этих 9 животных уже указывал на
      локальные пути и оставлен как есть; для животных без реального локального
      файла (морж, гребнистый крокодил, африканский буйвол, лось — были битые
      локальные пути; гризли, зебра, амурский тигр, африканский лев, горилла,
      комодский варан, императорский пингвин — были хотлинки на Unsplash) поле
      `imageUri` убрано из данных и стало опциональным в `src/types/index.ts`
      (`imageUri?: string`), `Level1Game.tsx` теперь не пытается грузить `<img>`,
      если `imageUri` нет, — сразу честный emoji-фолбэк без лишнего сетевого
      запроса и ошибки в консоли. Источники реальных фото для оставшихся 11
      животных — отдельная подзадача (см. «Баги» выше), т.к. требует либо
      доступа в интернет, либо платной AI-генерации с согласия пользователя.
